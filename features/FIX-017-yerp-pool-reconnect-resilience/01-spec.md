# FIX-017: Y-ERP 연결 끊김 후 서버 재시작 없이는 회복이 안 되는 문제

## 문제 상황
Y-ERP 서버 연결이 일시적으로 끊겼다가(사무실 인터넷/공유기 쪽 문제로 추정) 몇 분 뒤 복구됐는데도, 이미 떠 있던 개발 서버는 계속 "조회 중 오류가 발생했습니다"를 냈다. 서버를 재시작하니 바로 정상화됐다.

## 원인
`lib/yerp/client.ts`의 `yerpQuery`는 쿼리 실패 시 `pool` 참조를 `null`로 비워서 다음 요청이 새로 연결하게 하는데, 죽은 연결 풀 자체를 `close()`하지 않고 그냥 참조만 버렸다. 끊긴 소켓/재연결 타이머가 백그라운드에 남아 있으면 다음 새 연결 시도를 방해할 수 있어, 실제 Y-ERP가 복구된 뒤에도 그 프로세스에서는 계속 실패했다(프로세스를 재시작해야만 확실히 새로 시작).

## 기대 동작
연결 실패 시 풀 참조를 버릴 뿐 아니라 `close()`까지 호출해 확실히 정리한다. 이후 요청은 완전히 새로운 연결 풀로 시도되어, Y-ERP가 복구되면 서버 재시작 없이도 다음 요청부터 자동으로 정상화된다.

## 영향 범위
- `lib/yerp/client.ts`: `yerpQuery`의 오류 처리에 `connectedPool.close()` 추가
