# TASK-005: 부자재재고 파싱·업로드 — 아티팩트

## 상태: 배포 완료

## 구현 내용
부자재 입출고내역 엑셀의 12개 월별 시트를 모두 파싱해 저장하는 로직을 만들었다. 업로드 시 기존 데이터를 전부 지우고 새로 넣는 "전체 교체" 방식이다.

## 생성/수정된 파일
- `lib/saltfield/parse-materials.ts`: 월별 시트를 순회하며 5행부터 품명 있는 행만 파싱. **원본 엑셀의 이월재고/재고 값이 다른 시트를 참조하는 수식인데 캐시된 결과가 없는 경우가 많아**(실측 45개 품목 중 29개), 월 순서대로 훑으며 이월재고=전월 재고, 재고=이월재고+입고-출고, 재고금액=재고×단가로 직접 보정하는 로직을 추가했다
- `app/actions/saltfield-materials.ts`: `uploadMaterialInventory(formData)`(기존 tenant 데이터 삭제 후 재삽입), `getMaterialInventory(monthLabel?)`, `getMaterialMonths()`

## 완료 기준 확인
- [x] 실제 샘플 파일 업로드 시 12개 시트 540건 모두 파싱됨 — tsx로 직접 실행해 검증
- [x] 재업로드 시 기존 데이터 전체 교체(delete-then-insert) — 서버 액션에서 구현
- [x] 품명이 비어있는 행은 건너뜀
- [x] 염전관리팀이 아닌 계정은 업로드 액션 호출 시 거부 (`canManage`)
- [x] `npx tsc --noEmit` 통과

## 이슈 및 결정사항
- 보정 로직 추가 전에는 7월 기준 45건 중 29건(64%)이 재고 수량 null이었는데, 산술 보정 후 2건까지 줄었다. 남은 2건은 품명 자체가 월마다 바뀌는 품목(예: "20kg 맛있는천일염(2023년산)" → "(2024년산)"처럼 빈티지 연도가 매년 바뀜)이라 업체명+품명 매칭 체인이 끊겨서 그렇다 — 이건 데이터 자체의 명명 규칙 때문이라 코드로 완전히 해결하긴 어렵고, 원본에 값이 없으면 화면에서 "-"로 자연스럽게 표시하는 선에서 마무리했다.
- 8월(가장 최근 달)은 아직 시트 자체에 캐시된 값이 적어 보정 후에도 16건이 null로 남았다 — 다음 달 파일이 갱신되며 자연히 채워질 것으로 예상.
