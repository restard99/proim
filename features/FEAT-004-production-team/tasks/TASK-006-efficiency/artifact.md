# TASK-006: 생산효율(가동률) 탭 — 아티팩트

## 상태: 배포 완료

## 구현 내용
업로드된 생산일지를 기간(시작~종료 월) 선택해 집계할 수 있는 공정별 가동률과 정지시간 구성을 보여주는 "생산효율" 탭, 그리고 기간(월)별로 생산 흐름이 어떻게 이어져왔는지 보여주는 "인당생산성" 탭 2개로 구성했다.

사용자 피드백("생산일지 작업해준건 전체상황이 한눈에 들어오지도 않고 어떤지 알수가 없네", "생산효율탭에 지금 내용은 전체 녹여야 할것 같고, 인당생산성 탭에는 전체적으로 어떤흐름으로 생산이 되고 있는지 알 수 있었으면 좋겠어")을 반영해 다음과 같이 재구성했다:
- 원래 별도 모드였던 "생산일지 조회"(업로드/목록/원본 엑셀 그대로 보기)를 "생산효율" 탭 안으로 통합했다. 파일을 선택하면 그 파일만의 요약 카드(참여 공정 수/가동률/총 정지시간/인당 투입량)를 먼저 보여준 뒤 원본 표를 아래에 둬서, 숫자를 한눈에 파악한 다음 필요하면 원본까지 내려가 볼 수 있게 했다.
- "인당생산성" 탭은 공정별 스냅샷 대신, 기간(월) 단위로 가동률·인당 투입량이 어떻게 변해왔는지 보여주는 시계열 리스트로 다시 만들었다(오래된 기간 → 최근 기간 순, 막대바로 상대 크기 비교).
- 공통 집계 로직(`computeProcessEfficiency`)을 `lib/production-logs/efficiency.ts`로 분리해, 서버(여러 생산일지 누적 집계)와 클라이언트(선택한 파일 1건 요약) 양쪽에서 재사용한다.

## 생성/수정된 파일
- `lib/production-logs/efficiency.ts` (신규): `computeProcessEfficiency(sheetsList)` 순수 함수 — "총근무시간"·"실근무시간" 컬럼이 모두 있는 시트만 골라 공정별로 근무시간/정지시간/투입량/투입인원을 합산
- `app/actions/production-logs.ts`: `getProductionEfficiency(startPeriod?, endPeriod?)`, `getProductionLogPeriods()`, 신규 `getProductionTrend(startPeriod?, endPeriod?)` — 기간(월) 단위로 재집계해 시계열 반환. `periodSortKey()` — "YYYY년 M월" 형식을 정수로 변환해 범위/정렬 비교
- `components/production/ProductionLogView.tsx`: "생산효율"/"인당생산성" 2개 모드. `usePeriodRangeData()` 훅(제네릭)으로 기간 선택+조회 로직 공유. `EfficiencyView`(가동률 표), `TrendView`(기간별 흐름 리스트), `ProductionLogBrowser`(업로드/목록/파일 요약 카드/원본 표, 생산효율 탭 하단에 통합)

## 이슈 및 결정사항
컬럼명이 정확히 일치해야("총근무시간", "실근무시간" 등) 집계되므로, 원본 엑셀 헤더 문구가 달라지면 그 시트는 조용히 집계에서 빠진다 — 이는 "그럴듯하게 틀린 집계"보다 안전하다는 기존 설계 원칙과 동일하게 의도적으로 선택한 동작이다.

사용자가 참고 자료로 `F:\개발\ERP\주간_월간_업무보고_2026.08.09.xlsx`의 "인당생산성" 탭(생산효율지표: 정기근로생산량÷인원)을 제시했다. 이 파일을 직접 업로드/파싱하는 대신(구조가 완전히 다른 별도 리포트 — 이중 헤더+수식 기반 분기 집계), "인당 생산량" 개념만 차용해 우리가 이미 가진 생산일지 컬럼(투입량, 투입인원)으로 근사 지표를 추가했다. 완제품 생산량(kg)·정규 인원 기준인 원본 리포트와 산출 기준이 다르므로 화면에 안내 문구를 명시했다.

**버그 수정**: `app/actions/production-logs.ts`("use server" 파일)에서 `export type { ProcessEfficiency }`로 타입을 재-export했더니 Turbopack의 서버 액션 변환기가 이를 런타임 값 참조로 오인해 `ReferenceError: ProcessEfficiency is not defined`가 발생했다. "use server" 파일은 async 함수만 런타임 export로 다뤄야 안전하다는 걸 확인했고, 해당 타입을 쓰는 곳이 없어 재-export 자체를 제거해 해결했다.
