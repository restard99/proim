# 로그인 테스트 케이스

## 테스트 전 준비사항
- Supabase 프로젝트에 `lib/supabase/schema.sql`이 적용되어 있어야 한다.
- Supabase 대시보드 → Authentication → Providers → Email → "Confirm email"이 비활성화되어 있어야 한다.
- `lib/supabase/seed.sql`로 기본 테넌트와 관리자 계정(`시스템 관리자`)이 시딩되어 있어야 한다.
- `.env.local`에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `DEFAULT_TENANT_ID`가 설정되어 있어야 한다.
- `npm run dev`로 로컬 서버를 실행한 상태여야 한다.
- 관리자 계정의 로그인 정보(이름/비밀번호)를 알고 있어야 한다 (관리자는 `team`이 없으므로 로그인 화면에서 소속팀 선택 없이 처리되는지도 함께 확인 — 관리자 로그인은 대시보드에서 직접 확인하거나 별도 관리자 로그인 경로로 테스트한다).

## 정상 케이스

### TC-001: 신규 회원가입
**조건:** 처음 사용하는 이름+소속팀 조합
**단계:**
1. `/signup` 접속
2. 이름(예: "테스트원"), 소속팀(예: "생산팀"), 직급(팀원), 비밀번호(8자 이상), 비밀번호 확인을 입력
3. [가입 요청 보내기] 클릭
**기대 결과:** `/pending`으로 이동하고, 입력한 이름/소속팀/직급과 "승인 대기" 상태가 요약 카드에 표시됨
**결과:** [ ] 통과 / [ ] 실패

### TC-002: 관리자 승인 후 로그인
**조건:** TC-001에서 만든 계정이 아직 미승인 상태
**단계:**
1. 관리자 계정으로 `/login` 로그인
2. `/admin/approvals`에서 TC-001의 계정을 [승인] 클릭
3. 로그아웃 후 TC-001 계정의 이름/소속팀/비밀번호로 `/login` 재시도
**기대 결과:** 승인 목록에서 해당 계정이 사라지고, 로그인 시 `/`로 정상 진입함
**결과:** [ ] 통과 / [ ] 실패

### TC-003: 동명이인 다른 팀 가입
**조건:** TC-001과 이름은 같지만 소속팀이 다름
**단계:**
1. `/signup`에서 TC-001과 같은 이름, 다른 소속팀(예: "회계팀")으로 가입
**기대 결과:** 중복 오류 없이 가입되고 `/pending`으로 이동함
**결과:** [ ] 통과 / [ ] 실패

### TC-004: 관리자 반려 처리
**조건:** 대기 중인 가입 요청이 있음
**단계:**
1. 관리자 계정으로 `/admin/approvals` 접속
2. 임의의 대기 요청에 [반려] 클릭
**기대 결과:** 목록에서 해당 요청이 사라짐. 반려된 계정으로 로그인 시도 시 TC-006과 동일하게 미승인 오류가 뜸 (반려도 승인되지 않은 상태로 취급)
**결과:** [ ] 통과 / [ ] 실패

### TC-005: 비로그인 상태 접근 가드
**조건:** 로그아웃 상태
**단계:**
1. 브라우저에서 `/`, `/pending`, `/admin/approvals` 등 보호된 경로로 직접 접속
**기대 결과:** 모두 `/login`으로 리다이렉트됨
**결과:** [ ] 통과 / [ ] 실패

### TC-006: 일반 사용자의 관리자 페이지 접근 차단
**조건:** 승인된 일반(팀원/팀장/대표) 계정으로 로그인한 상태
**단계:**
1. 주소창에 `/admin/approvals` 직접 입력
**기대 결과:** `/`로 리다이렉트되어 관리자 화면이 보이지 않음
