# TASK-001: 헤더 라벨 기반 동적 열 매핑 — 아티팩트

## 상태: 완료

## 수정 내용
`parseProductionRequestWorkbook`이 열 위치를 하드코딩하지 않고, 헤더 행의 실제 문구("낱개수", "입수", "박스수" 등)를 읽어 각 필드가 몇 번째 열에 있는지 찾도록 바꿨다. 새로 추가된 "구분" 열은 별도 필드(`category`)로 분리해서 저장하고, 화면에도 "제품명" 바로 뒤에 "구분" 열을 추가했다. 개발 중간에 사용자 요청으로 방향이 한 번 바뀌었다 — 처음엔 "구분" 값을 비고(remark)에 합쳐 넣으려 했으나, 최종적으로는 원본 파일과 동일하게 별도 열로 그 자리에 넣는 것으로 결정.

## 수정된 파일
- `lib/production-requests/parse.ts`: 헤더 라벨 기반 열 매핑(`buildColumnMap`/`colToField`) 도입, `category` 필드 추가, 병합 셀 강조 로직도 동적 열번호 기준으로 수정, 매핑 안 된 나머지 열은 비고(remark)로 모음
- `app/actions/production-requests.ts`: `getProductionRequestDetail`의 기본값 매핑에 `category` 추가
- `components/inventory/ProductionRequestView.tsx`: "구분" 열을 표(제품명 다음)에 추가, 소계 행에 빈 셀 1개 추가로 열 개수 맞춤. (겸사겸사 사용자 요청으로 비고 열 너비를 90px→260px로 넓히고 줄바꿈 표시로 변경 — 이전엔 90px 고정폭+말줄임으로 내용이 자주 잘렸음)

## 이슈 및 결정사항
당초 계획(spec)은 "구분" 값을 비고(remark)에 합쳐 넣는 것이었으나, 개발 도중 사용자가 "구분을 그 자리에 넣어달라"고 요청을 바꿔 최종적으로 전용 `category` 필드 + 전용 열로 구현했다. 함께 "비고란이 좁아서 내용이 잘린다"는 피드백을 받아 비고 열도 넓히고 줄바꿈 표시로 바꿨다(이건 이번 버그와 별개의 요청이지만 같은 화면·같은 파일 수정 범위라 함께 반영).
