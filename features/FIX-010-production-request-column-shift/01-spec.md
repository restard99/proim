# FIX-010: 생산의뢰서 업로드 - 헤더 열 추가 시 데이터 밀림

## 문제 상황
생산의뢰서 엑셀 업로드(`/production-requests`) 시 최근 파일(`★생산의뢰서(0902).xlsx`)에서 데이터가 깨져서 들어온다. 원본 파일의 헤더 행에 "제품명"과 "낱개수" 사이에 새로 "구분" 열이 추가되어 있는데, 파서(`lib/production-requests/parse.ts`)가 열 위치를 고정 인덱스(2번째 열=낱개수, 3번째 열=입수...)로 읽기 때문에, "구분" 열이 끼어들면서 그 뒤 모든 값이 한 칸씩 밀려 잘못된 항목에 들어간다.

실제 파싱 결과 확인: 낱개수(count)는 전부 빈 값, 입수(pack) 칸에 낱개수 값, 박스수(boxes) 칸에 입수 값... 식으로 전부 한 칸씩 밀림. 소계(합계) 행도 동일하게 밀림.

## 현재 동작
- 헤더 행에서 "제품명"이 있는 행만 찾고, 그 아래 항목 행은 열 위치를 하드코딩된 순서(name, count, pack, boxes, weightKg, pl, eaPerPl, note, loadType, dueDate)로 읽는다.
- 원본 파일에 열이 추가/재배치되면 감지하지 못하고 그대로 밀린 값을 저장한다.
- 항목이 1개 이상 파싱되면(빈 배열이 아니면) 업로드 자체는 "성공"으로 처리되어, 사용자는 화면에 표시된 숫자가 이상해진 뒤에야 문제를 알아챈다.

## 기대 동작
- 헤더 행의 실제 문구("낱개수", "입수", "박스수", "중량(kg)", "PL", "EA/PL", "특이사항", "적재방식", "완료요청일")를 읽어서 각 필드가 몇 번째 열에 있는지 동적으로 찾는다. 열이 추가되거나 순서가 바뀌어도 라벨 기준으로 정확한 열을 찾아 안전하게 파싱한다.
- 새로 추가된 "구분" 열의 값(예: "3공장")은 버리지 않고 비고(remark)란에 포함해서 저장한다.
- 기존 파일(구분 열이 없는 예전 포맷)도 동일한 방식으로 문제없이 계속 파싱되어야 한다(하위 호환).

## 영향 범위
- `lib/production-requests/parse.ts`: 헤더 기반 동적 열 매핑으로 변경
- `components/inventory/ProductionRequestView.tsx` (또는 해당 표시 컴포넌트): 비고(remark)에 "구분" 값이 포함되어 보이는지 확인 (표시 로직 자체는 이미 remark 필드를 쓰고 있어 수정 불필요할 가능성 높음, 확인만)
