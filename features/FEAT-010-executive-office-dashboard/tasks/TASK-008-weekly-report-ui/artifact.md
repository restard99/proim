# TASK-008: 주간업무보고 화면 UI — 아티팩트

## 상태: 완료 (브라우저 최종 확인은 6단계 테스트에서 진행)

## 구현 내용
`02-design.html`의 주간업무보고 화면을 실제 컴포넌트로 옮겼다. 6개 페이지 탭, 지난주/다음주 네비게이션(주 단위로 서버 액션 재호출), 목표 미입력 시 "미입력" 표시, 댓글 목록/작성을 구현했다. 표 스타일(`grid-table`, `total-row`)은 `02-design.html`의 것을 그대로 `globals.css`에 옮겨 실제 앱에서도 동일하게 보이도록 했다.

## 생성/수정된 파일
- `app/(app)/executive/report/page.tsx` (신규): 권한 체크(`canViewExecutive`) + 이번 주 월요일 계산 + 초기 데이터 로드
- `components/executive/WeeklyReportView.tsx` (신규): 6개 페이지 탭 전환, 주차 네비게이션, 댓글 UI
- `app/globals.css`: `02-design.html`의 `.grid-table`/`.total-row` 표 스타일 이식

## 완료 기준 확인
- [x] 6개 페이지 탭 전환 동작 (클라이언트 상태로 즉시 전환)
- [x] 지난주/다음주 이동 시 해당 주 데이터로 갱신 (`getWeeklyReport`/`getComments` 재호출)
- [x] 목표 미입력 주는 계획 칸에 "미입력" 표시 — `won()`/`kg()` 헬퍼가 `null`을 "미입력"으로 렌더링
- [x] 댓글 작성/조회 동작 (`postComment` 성공 시 목록 재조회)
- [x] `npx tsc --noEmit` 통과
- [ ] 브라우저에서 실제 데이터로 확인 — admin/임원실 로그인 정보가 없어 이 세션에서는 직접 확인하지 못함. 6단계 테스트 케이스에서 사용자가 확인 예정

## 이슈 및 결정사항
컴포넌트 자체 검증(타입체크, 라우트 컴파일, 하위 데이터 함수 실데이터 검증)은 마쳤지만, 실제 로그인 세션으로 화면을 열어보는 것은 이 세션에서 admin/임원실 계정 비밀번호를 알 수 없어 하지 못했다. 6단계에서 사용자가 직접 확인하는 걸로 남겨둔다.
