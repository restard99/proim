# FIX-007: 로그인 시 다른 소속팀을 선택해도 로그인되는 문제

## 문제 상황
사용자가 완전히 로그아웃된 상태에서 `/login`에 접속해 이름을 입력하고, 소속팀 드롭다운에서 본인의 실제 팀이 아닌 **다른 팀**을 선택한 뒤 로그인을 시도했는데도 로그인이 성공했다고 보고됨.

## 검증한 내용 (원인 규명 과정)
- **서버 로직/DB 자체는 정상 동작을 확인함.** `signIn` 서버 액션이 호출하는 `lookup_auth_email(tenant_id, full_name, team)` RPC를 실서비스 DB에 대해 anon key로 직접 재현 테스트한 결과, 이름은 맞고 팀만 다르게 넘기면 `null`을 반환한다 (즉 이메일을 못 찾아 `invalid-credentials`로 정상 처리됨).
- 전체 프로필(10명) 중 동명이인(같은 이름, 다른 팀)은 존재하지 않아, "이름은 같지만 팀이 다른 두 계정이 우연히 같은 비밀번호를 가져서 로그인된" 시나리오도 배제됨.
- 별도로 테스트 계정(이름: 버그테스트유저, 팀: 생산팀)을 만들어 "영업팀"으로 로그인 시도 → RPC가 `null` 반환, 예상대로 차단됨을 재확인. (테스트 후 계정은 삭제함)
- 즉, **서버가 실제로 인증을 승인한 것이라면 DB의 이름+팀 조합이 우연히 일치했거나(가능성 낮음, 배제됨), 클라이언트가 사용자가 고른 값과 다른 팀 값을 서버로 보냈을 가능성**이 남는다.

### 발견한 클라이언트 버그 (유력한 원인)
`components/auth/LoginForm.tsx`의 이름 입력창 `onBlur` 핸들러(`handleNameBlur`)가 다음과 같이 동작한다:
1. 이름 입력 후 포커스가 빠지면 `lookupTeamsByName(name)`을 비동기로 호출한다.
2. 응답이 도착하면 (동명이인이 없어 팀이 정확히 1개로 특정되면) `teamSelectRef.current.value`를 **그 팀으로 강제로 덮어쓴다** — React state가 아닌 `<select>` DOM을 직접 조작.
3. 이 덮어쓰기는 **사용자가 그 사이에 드롭다운에서 이미 다른 팀을 수동으로 선택했는지 여부를 전혀 확인하지 않는다.**

즉, 이름 입력 → Tab/클릭으로 소속팀 드롭다운으로 이동해 빠르게 다른 팀을 고르는 흐름에서, 뒤늦게 도착한 자동완성 응답이 사용자의 선택을 조용히 실제 소속팀으로 되돌려버릴 수 있다. 이 경우 사용자는 "다른 팀을 선택했다"고 인지하지만 실제 제출되는 값은 본인의 진짜 팀이 되어 로그인이 성공한다 — 화면에는 결국 실제(정상) 계정으로 로그인된 것으로 보인다.

이 레이스 컨디션은 실제 보안 우회는 아니지만(자동완성이 항상 "그 이름의 진짜 소속팀"으로만 값을 채우므로, 남의 계정으로 들어가는 것은 불가능), 사용자가 "다른 팀을 선택했는데도 로그인이 됐다"고 느끼게 만드는 원인으로 가장 유력하다. 사용자의 의도적인 선택을 예고 없이 덮어쓰는 것 자체도 UX상 결함이다.

## 현재 동작
- 이름 입력 후 소속팀 자동완성 응답이 늦게 도착하면, 사용자가 이미 수동으로 선택해둔 소속팀 값을 조건 없이 덮어쓴다.

## 기대 동작
- 사용자가 소속팀 드롭다운을 한 번이라도 직접 조작(선택)한 뒤에는, 이름 자동완성 응답이 늦게 도착하더라도 그 값을 덮어쓰지 않는다.
- 다른 팀을 선택하고 로그인을 시도하면 (실제 계정의 팀과 다르면) 항상 로그인이 거부된다 — 이 부분은 이미 서버/DB 단에서 검증되어 정상이므로 회귀만 없으면 됨.

## 영향 범위
- `components/auth/LoginForm.tsx` (수정 대상)
- `app/actions/auth.ts`의 `signIn`, `lookup_auth_email` RPC — 수정 없음 (검증 결과 정상)
