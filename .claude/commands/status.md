# Status — 개발 현황 대시보드

`features/` 폴더를 스캔해 모든 기능의 현재 개발 단계를 표로 보여줍니다.

## 동작 방식

1. `features/` 폴더의 모든 하위 폴더 목록을 가져온다 (FEAT-NNN-* 및 FIX-NNN-* 형태)
2. 각 폴더에서 다음 파일 존재 여부를 확인해 현재 단계를 판정한다:
   - `tasks/` 내 모든 artifact.md에 "배포 완료" 포함 → **완료**
   - `06-test-cases.md` 존재 → **6/8 테스트 중** (FEAT) / **5/6 테스트 중** (FIX)
   - `tasks/` 폴더 내 artifact.md 하나라도 존재 → **5/8 개발중** (FEAT) / **4/6 개발중** (FIX)
   - `tasks/` 폴더 내 spec.md 하나라도 존재 → **4/8 태스크분리** (FEAT) / **3/6 태스크분리** (FIX)
   - `03-decisions.md` 존재 → **3/8 결정완료** (FEAT) / **2/6 결정완료** (FIX)
   - `02-design.html` 존재 → **2/8 디자인** (FEAT만 해당)
   - `01-spec.md` 존재 → **1/8 아이디에이션** (FEAT) / **1/6 문제정의** (FIX)
   - 아무것도 없음 → **시작전**
3. 각 폴더에서 가장 최근에 수정된 파일의 날짜를 가져온다
4. 결과를 표로 출력한다

## 출력 형식

```
📊 삼선 ERP 개발 현황 (YYYY-MM-DD 기준)

┌─────────────────────────┬────────────────┬──────────────────┐
│ 기능                    │ 현재 단계       │ 마지막 업데이트   │
├─────────────────────────┼────────────────┼──────────────────┤
│ FEAT-001 user-login     │ 5/8 개발중      │ 2026-07-30       │
│ FEAT-002 dashboard      │ 2/8 디자인      │ 2026-07-29       │
│ FIX-001 button-error    │ 완료            │ 2026-07-28       │
└─────────────────────────┴────────────────┴──────────────────┘

진행 중: 2개 | 완료: 1개 | 전체: 3개
```

5. features/ 폴더가 비어 있으면: "아직 개발 중인 기능이 없습니다. `/new-feature`로 첫 기능을 시작해보세요!"라고 안내한다
6. 표 출력 후 "자세히 볼 기능이 있으면 알려주세요."라고 안내한다
